🔧 Instalar / migrar el proyecto

Poner el sistema a andar en una PC — sea igual a este equipo o desde cero.

⚙️
GUIA_INSTALACION.html HTML interactivo

Versión exacta de PHP/extensiones/drivers de SQL Server necesarios, instalación desde cero (clon nuevo + base de datos), credenciales iniciales, checklist y errores típicos. Único documento de instalación — antes había dos con contenido repetido, ahora es uno solo.

🏗️ Cómo está armado el sistema

Referencia técnica de arquitectura — para entender o modificar el código.

🧩
GUIA_CORE_PORTAL_APM.html HTML interactivo

El framework propio del portal (Router, Controller, Database, MFA, config) más el puente de sesión real entre Portal/TH/Bienes/Bitácoras — código a código, verificado línea por línea.

🏛️
GUIA_CENTRAL_FUNCIONES.html HTML interactivo

Qué hace el Portal APM como aplicación en sí — el hub central (login, permisos, menú, administración), sin entrar en los módulos integrados.

🔐
GUIA_SEGURIDAD_CONTRASENAS.html HTML interactivo

El esquema híbrido de contraseñas (SHA-256 en el navegador + pepper compartido + BCrypt en el servidor) usado en las 4 aplicaciones.

🔗
GUIA_VINCULACION_USUARIOS_ENTRE_MODULOS.html HTML interactivo

Explicación simple (sin conocimiento previo de BD) de cómo se vincula un usuario entre CORE, módulos actuales y futuros — incluido el portal de trámites en línea que se planea a futuro. Complementa a GUIA_SSO_LOGIN_ENTRE_MODULOS.md, no lo repite.

🌐
GUIA_SSO_LOGIN_ENTRE_MODULOS.md Markdown

Referencia técnica profunda de los 5 sp_SSO_* — para apps que no comparten sesión PHP con el portal (otro servidor, otro lenguaje). El detalle código-a-código que la guía de vinculación no repite.

🗺️ Usar / probar el sistema ya instalado

Para alguien que ya tiene el proyecto corriendo y quiere recorrerlo.

🧭
GUIA_VISUAL_NAVEGACION.html HTML interactivo

Mapa de todas las pantallas del sistema con link directo a cada una, credenciales de acceso y un checklist marcable para ir probando módulo por módulo.

🛠️ Desarrollar / actualizar módulos

Para agregar un módulo nuevo al portal, o traer una versión actualizada de uno existente.

📦
GUIA_MODULOS_NUEVOS_Y_ACTUALIZACIONES.md Markdown

Dos partes independientes: cómo construir e integrar un módulo nuevo, y cómo traer una versión nueva de uno ya integrado sin romper nada — basada en una actualización real hecha en el proyecto.

🗂️ Meta / histórico

No son guías de uso — son contexto de proceso y decisiones ya cerradas.

💬
CONTEXTO_PARA_NUEVO_CHAT.md Markdown

Puente para arrancar una conversación nueva con un asistente de IA sin perder el hilo del proyecto. No es documentación para un desarrollador humano nuevo.

✅
PROPUESTA_SEGURIDAD_2FA_TOKENS_RESET.md Ya implementado

Propuesta original de 2FA/endurecimiento de sesiones/recuperación de contraseña (2026-08-06). Queda como registro histórico de la decisión — el MFA/TOTP descrito ahí ya está implementado y funcionando; ver GUIA_CORE_PORTAL_APM.html §11 para cómo quedó realmente.

🛠️ Scripts (no son guías, son herramientas) backup_completo_5_bases.sql y generar_backups_sql2014.ps1 — generan backups de las 5 bases del sistema (nativo .bak y portable compatible con SQL Server 2014+, respectivamente). Se usan desde GUIA_INSTALACION.html §7.2 al migrar a otra PC.
